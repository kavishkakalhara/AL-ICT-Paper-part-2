  1. පයිතන් ක්‍රමලේඛනය — ශ්‍රිත (functions), ලැයිස්තු, ශබ්දකෝෂ (dict), tuple, ගොනු කියවීම/ලිවීම, exceptions. 25% බර

  3. වෙබ් — HTML පෝරම, PHP–MySQL සම්බන්ධ කිරීමේ සම්මත කේත කොටස.

දින 2 — නිතරම එන කෙටි මාතෘකා (පැය 8–10)
  1. ජාලකරණය — OSI/TCP-IP, අනුජාලකරණය (VLSM), උපාංග, ආරක්ෂාව, ස්ථල විද්‍යාව.
  2. ඩිජිටල් තර්කනය — බූලියන් නීති, කාර්නෝ සිතියම, සරල පරිපථ සැලසුම, ෆ්ලිප්-ෆ්ලොප්.
  3. පද්ධති විශ්ලේෂණය — SDLC, SSADM, ශක්‍යතා වර්ග, DFD, පරීක්ෂණ, යෙදවීමේ ක්‍රම.
  4. මෙහෙයුම් පද්ධතිය — ක්‍රියාවලි තත්ත්ව, පිටුකරණය, FAT, කාලසටහන්කරණය.

  1. උදේ: පුරෝකථන පත්‍ර 2 සම්පූර්ණයෙන් (පැය 3 කාලයට) ලියන්න.
  2. දහවල්: ෆ්ලෑෂ් කාඩ් 60ම එකින් එක — නොදන්නේ සලකුණු කරන්න.
  3. සවස: කේත බැංකුව (Python / PHP / SQL / Subnet / Boolean) පිටපත් කර ලියන්න — අතින්ම ලියන්න.
  4. රාත්‍රී: IoT (Arduino pins) + ඊ-ව්‍යාපාර + නව ප්‍රවණතා + පරිගණක ආචාර ධර්ම. විනාඩි 30ක් පමණයි.
  5. විභාගයට පෙර උදේ: මෙම පිටුවේ "විභාග ශාලාවේ උපදෙස්" කියවා යන්න. අලුත් දෙයක් පාඩම් නොකරන්න.

01 ICT මූලික සංකල්ප හා සමාජ බලපෑම

1. දත්ත හා තොරතුරු

දත්ත (Data)තොරතුරු (Information)
අර්ථයසැකසූ නොමැති අමු සංඛ්‍යා, අකුරු, සංකේත, රූප, ශබ්දසන්දර්භයක් තුළ අර්ථවත් ලෙස සැකසූ දත්ත
ස්වභාවයතේරුමක් නැති, තීරණ ගැනීමට ප්‍රයෝජනවත් නැතිතීරණ ගැනීමට උපකාරී වන අර්ථවත් ප්‍රතිදානය
උදාහරණය65, 70, 72 (වෙන් වෙන් අගයන්)"සිසුන් තිදෙනෙකුගේ ලකුණු 65, 70, 72 — සාමාන්‍යය 69"

තොරතුරුවල ගුණාංග (Quality of Information) — නි කා ස අ ව

  • නිරවද්‍යතාව (Accuracy) — වැරදි නැති වීම
  • කාලීනතාව (Timeliness) — අවශ්‍ය වේලාවට ලැබීම (කාලයත් සමග වටිනාකම අඩු වේ)
  • සම්පූර්ණත්වය (Completeness) — අවශ්‍ය සියලු විස්තර තිබීම
  • අදාළත්වය / සුදුසුතාව (Relevance) — තීරණයට සම්බන්ධ වීම
  • වටිනාකම (Value) — ලබා ගැනීමේ වියදමට වඩා ප්‍රයෝජනය වැඩි වීම
  • + පැහැදිලි බව, සංක්ෂිප්ත බව, විශ්වාසනීයත්වය, සුරක්ෂිතතාව

2. දත්ත සැකසුම් ජීවන චක්‍රය (Data Processing Cycle)

ආදානය (Input/Data gathering) → සැකසීම (Processing) → ප්‍රතිදානය (Output) → ගබඩා කිරීම (Storage) → බෙදා හැරීම (Dissemination)

  • දත්ත රැස් කිරීමේ ක්‍රම: අතින් (මිනිස් ක්‍රියාකාරකම්), ස්වයංක්‍රීය (සංවේදක, ස්කෑනර්), OMR / OCR / MICR / BCR / RFID / ස්මාර්ට් කාඩ්පත්
  • දත්ත වලංගුකරණය (Validation): වර්ගය (type), දිග (length), පරාසය (range), ආකෘතිය (format), පැවැත්ම (presence/check digit), සීමා (limit)
  • දත්ත සත්‍යාපනය (Verification): දෙවරක් ඇතුළත් කිරීම, සංඛ්‍යාංක සත්‍යාපනය (check digit)
  • සැකසුම් ක්‍රම: කණ්ඩායම් (Batch) හා තත්කාලීන (Real-time / Online)

3. වියුක්ත තොරතුරු ආකෘතිය (Abstract Model)

ආදානය (Input) → සැකසීම (Process) → ප්‍රතිදානය (Output) — ඕනෑම පද්ධතියක් විස්තර කිරීමට යොදා ගත හැකි පොදු ආකෘතියයි. 2024 වසරේ A කොටසේ මෙයින් ප්‍රශ්නයක් ආවා.

විභාග උදාහරණය "අන්තර්ජාල පොත් සාප්පුවකට පිවිසීම" සඳහා:
ආදානය: පරිශීලක නාමය හා මුරපදය | සැකසීම: දත්ත සමුදායේ ඇති තොරතුරු සමග සසඳා සත්‍යාපනය | ප්‍රතිදානය: "සාර්ථකව පිවිසුණා" යන පණිවිඩය / ගිණුම් පිටුව

4. පරිගණක පද්ධතියේ සංරචක

කොටසඅර්ථය / උදාහරණ
දෘඪාංග (Hardware)ස්පර්ශ කළ හැකි භෞතික කොටස් — CPU, මතකය, යතුරුපුවරුව, මුද්‍රණ යන්ත්‍රය
මෘදුකාංග (Software)දෘඪාංග ක්‍රියාත්මක කරවන වැඩසටහන් — පද්ධති මෘදුකාංග (OS), යෙදුම් මෘදුකාංග (App), උපයෝගිතා (Utility)
ස්ථිරාංග (Firmware)දෘඪාංගයේම කාවැද්දූ (ROM/Flash) මෘදුකාංගය — BIOS/UEFI

භාණ්ඩමය (Proprietary) vs විවෘත මූලාශ්‍ර (Open Source) මෘදුකාංග

ලක්ෂණයභාණ්ඩමයවිවෘත මූලාශ්‍ර
මූල කේතය (source code)සඟවා ඇත, වෙනස් කළ නොහැකනිදහසේ ලබා ගත හැක, වෙනස් කළ හැක
පිරිවැයබලපත්‍ර ගාස්තුවක් අය කරයිසාමාන්‍යයෙන් නොමිලේ
සහාය (support)නිෂ්පාදකයාගෙන් සහතික කළ සහායප්‍රජා සහාය (community)
ස්ථාපනය/සැකසුමපහසුයි — නිෂ්පාදකයාම සකසා දෙයිතාක්ෂණික දැනුම අවශ්‍යයි
උදාහරණWindows, MS Office, AdobeLinux, LibreOffice, Apache, MySQL, Python

5. ICT හි සමාජ, ආර්ථික හා පාරිසරික බලපෑම

✅ යහපත් බලපෑම්
  • වේගවත් හා නිරවද්‍ය සන්නිවේදනය (ඊ-තැපෑල, සමාජ මාධ්‍ය)
  • කාර්යක්ෂමතාව වැඩිවීම හා කාලය ඉතිරි කිරීම
  • නව රැකියා අවස්ථා (ඊ-වාණිජ්‍යය, දුරස්ථ සේවය — telecommuting)
  • අධ්‍යාපනය හා සෞඛ්‍ය සේවාවල ගුණාත්මකභාවය
  • ඊ-රාජ්‍ය (e-Government) — පුරවැසියන්ට පහසු සේවා
  • කඩදාසි භාවිතය අඩුවීම (green ICT)
❌ අයහපත් බලපෑම්
  • රැකියා අහිමි වීම (ස්වයංක්‍රීයකරණය)
  • සෞඛ්‍ය ගැටළු — ඇස් ආබාධ, RSI, කොන්දේ කැක්කුම, මානසික ආතතිය
  • පරිගණක අපරාධ, වංචා, අනන්‍යතා සොරකම් (identity theft)
  • සමාජ හුදෙකලාව, සයිබර් හිරිහැර (cyber bullying)
  • ගෝලීය උණුසුම — දත්ත මධ්‍යස්ථානවල විශාල විදුලි පරිභෝජනය හා සිසිලනය
  • ඊ-අපද්‍රව්‍ය (e-waste) — විෂ සහිත රසායනික ද්‍රව්‍ය පරිසරයට
  • ඩිජිටල් පරතරය (Digital divide) — තාක්ෂණයට ප්‍රවේශය නොමැති පිරිස් තවත් පසුගාමී වීම

6. පරිගණක ආචාර ධර්ම හා නෛතික කරුණු

  • බුද්ධිමය දේපළ අයිතිය (Intellectual Property) — නිර්මාණකරුවාගේ අයිතිය; ප්‍රකාශන අයිතිය (copyright), පේටන්ට්, වෙළඳ ලකුණු, වෙළඳ රහස්
  • සාහිත්‍යමය සොරකම (Plagiarism) — අනුන්ගේ නිර්මාණ තමන්ගේ ලෙස ඉදිරිපත් කිරීම. ICT නිසා පිටපත් කිරීම (copy–paste) ඉතා පහසු වීම නිසා මෙය වැඩි වී ඇත.
  • පෞද්ගලිකත්වය (Privacy) — අනුමැතියකින් තොරව පුද්ගලික දත්ත රැස් කිරීම/භාවිතය (2024 ප්‍රශ්නයක්)
  • දත්ත ආරක්ෂණ පනත අංක 9 (2022) — ශ්‍රී ලංකාවේ පුද්ගලික දත්ත ආරක්ෂණ නීතිය
  • පරිගණක අපරාධ පනත අංක 24 (2007) — අනවසර ප්‍රවේශය, දත්ත විනාශ කිරීම
  • සදාචාරාත්මක භාවිතය: බලපත්‍රලාභී මෘදුකාංග පමණක් භාවිතය, ප්‍රභවය සඳහන් කිරීම, අන් අයගේ ගොනුවලට හානි නොකිරීම
🎯 මතක තබා ගන්න (2026 සඳහා වැදගත්ම) "තොරතුරුවල ගුණාංග 5", "වියුක්ත ආකෘතිය", "භාණ්ඩමය vs විවෘත මූලාශ්‍ර", "ICT නිසා ගෝලීය උණුසුමට හේතුව", "ICT නිසා සාහිත්‍යමය සොරකම වැඩිවීමට හේතුව", "අනුමැතියකින් තොරව දත්ත රැස් කිරීම = පෞද්ගලිකත්ව ගැටළුව" — මේවා වචනයෙන් වචනයටම ප්‍රශ්න ලෙස එන්න පුළුවන්.
02 පරිගණක වාස්තුවිද්‍යාව හා දත්ත නිරූපණය

1. වොන් නියුමන් වාස්තුවිද්‍යාව (Von Neumann)

  • උපදෙස් හා දත්ත එකම මතකයක ගබඩා කිරීම (stored program concept)
  • ප්‍රධාන ඒකක: මතක ඒකකය (MU), අංක ගණිත හා තාර්කික ඒකකය (ALU), පාලන ඒකකය (CU), ආදාන ඒකක, ප්‍රතිදාන ඒකකය

අර්ධ එකතුකය (Half Adder)බිට්ටු 2ක් එකතු කරයිSum = A⊕B ; Carry = AB

  • අනුක්‍රමික පරිපථවල ප්‍රතිදානය වර්තමාන ආදානය හා පෙර තත්ත්වය යන දෙකම මත රඳා පවතී (මතකය ඇත). සංයෝජන පරිපථවල එසේ නොවේ.
  • භාවිත: රෙජිස්ටර් (registers), කවුන්ටර (counters), RAM සෛල
🎯 සැලසුම් ප්‍රශ්නයක් ආවොත් (design a circuit)
① විචල්‍යයන් නම් කරන්න (උදා: MSB සිට) → ② සත්‍යතා වගුව/සත්‍ය සංයෝජන ලැයිස්තුව → ③ K-map එකෙන් සරලතම ප්‍රකාශනය → ④ පරිපථ සටහන (ද්වාර අඳින්න, සලකුණු සහිතව) → ⑤ "ආපසු හරවන ලද ආදාන ද ඇත" යැයි සඳහන් නම් NOT ද්වාර අඳින්න එපා.
04 මෙහෙයුම් පද්ධතිය හා මතක කළමනාකරණය

1. මෙහෙයුම් පද්ධතියේ කාර්යයන්

ක්‍රියාවලි කළමනාකරණය, මතක කළමනාකරණය, ගොනු/තැටි කළමනාකරණය, ආදාන–ප්‍රතිදාන කළමනාකරණය, ආරක්ෂාව හා පරිශීලක අතුරු මුහුණත (UI), ජාලකරණය.

වර්ගයවිස්තරයඋදාහරණය
කණ්ඩායම් (Batch)රැකියා පෙළක් අධීක්ෂණයකින් තොරව ක්‍රියාත්මක වේපැරණි mainframe
කාල බෙදාගැනීමේ (Time-sharing)සෑම පරිශීලකයෙකුටම කුඩා කාල ප්‍රමාණයක් (time quantum)Unix, Linux
බහු ක්‍රමලේඛනය (Multiprogramming)මතකයේ ක්‍රියාවලි කිහිපයක්; CPU නිෂ්ක්‍රීය නොවේනූතන OS සියල්ලම
තත්කාලීන (Real-time)නියමිත කාල සීමාවක් තුළ ප්‍රතිචාර (hard/soft)වෛද්‍ය උපකරණ, ගුවන් පාලනය
බෙදා හරින ලද (Distributed)පරිගණක කිහිපයක් එකටCluster OS
කාවැද්දූ (Embedded)කැපවූ උපාංග සඳහාAndroid, RTOS, Arduino firmware

2. ක්‍රියාවලිය හා එහි තත්ත්ව (Process States)

නව (New) → සූදානම් (Ready) ⇄ ක්‍රියාත්මක (Running) → අවසන් (Terminated)
                        ↑                    ↓
                        └── අවහිර (Blocked/Waiting) ←┘  (I/O සඳහා බලා සිටී)
  • Ready → Running: කාලසටහන්කරු (scheduler) විසින් තෝරා ගනී (dispatch)
  • Running → Blocked: I/O හෝ සම්පතක් සඳහා ඉල්ලීමක් කරයි
  • Running → Ready: කාල කොටස (time quantum) අවසන් වීම හෝ බාධාව (interrupt)
  • Blocked → Ready: I/O සම්පූර්ණ වීම
  • සන්දර්භ මාරුව (Context Switch): එක් ක්‍රියාවලියකින් තවත් ක්‍රියාවලියකට CPU මාරු කිරීම. වර්තමාන තත්ත්වය ක්‍රියාවලි පාලන කොටසෙහි (PCB) සුරැකේ — පසුව එතැනින්ම යළි ආරම්භ කළ හැක්කේ මේ නිසයි. (2025 A4 ප්‍රශ්නය)
  • ක්‍රියාවලියක් අවහිර (Blocked) තත්ත්වයට යැවීමේ වාසිය: CPU එය එනතුරු නිෂ්ක්‍රීයව නොසිට වෙනත් ක්‍රියාවලියක් ක්‍රියාත්මක කරයි → CPU ප්‍රයෝජනය (utilization) උපරිම වේ.
  • ක්‍රියාවලිය (process) හා පොට (thread): පොට යනු ක්‍රියාවලියක් තුළ ඇති සැහැල්ලු ක්‍රියාත්මක ඒකකයයි — මතකය බෙදා ගනී.

3. CPU කාලසටහන්කරණ ඇල්ගොරිතම

ඇල්ගොරිතමයක්‍රියාත්මක වන ආකාරයවාසි / අවාසි
FCFS (පළමුව පැමිණි අයට පළමුව)පැමිණි පිළිවෙලටමසරලයි; කෙටි ක්‍රියාවලි දිගු ඒවාට පසුව බලා සිටීමට සිදුවේ (convoy effect)
SJF (කෙටිම කාර්යයට ප්‍රමුඛතාව)අවම ක්‍රියාත්මක කාලය ඇති ක්‍රියාවලියටසාමාන්‍ය බලා සිටීමේ කාලය අවමයි; දිගු ක්‍රියාවලි කුසගින්නෙන් (starvation) පෙළේ
ප්‍රමුඛතාව (Priority)ඉහළම ප්‍රමුඛතාව ඇති ක්‍රියාවලියටවැදගත් කාර්යයන්ට ප්‍රමුඛතාව; starvation → වයස්ගත වීම (aging) විසඳුම
රවුන්ඩ් රොබින් (RR)සෑම ක්‍රියාවලියකටම සමාන කාල කොටසක් (time quantum)සාධාරණයි, ප්‍රතිචාරශීලීයි; quantum කුඩා නම් context switch වැඩි වී කාර්යක්ෂමතාව අඩු වේ
ගණනය කිරීම් සූත්‍ර
• සම්පූර්ණ කිරීමේ කාලය (Turnaround Time) = අවසන් වූ වේලාව − පැමිණි වේලාව
• බලා සිටීමේ කාලය (Waiting Time) = සම්පූර්ණ කිරීමේ කාලය − ක්‍රියාත්මක (burst) කාලය
• ප්‍රතිචාර කාලය (Response Time) = පළමු ප්‍රතිචාරය ලැබෙන වේලාව − පැමිණි වේලාව
• Gantt සටහනක් අඳින්න — සියලු ක්‍රියාවලි පිළිවෙලට දමන්න.

4. මතක කළමනාකරණය

  • පිටුකරණය (Paging): තාර්කික මතකය පිටු (pages) ලෙසත් භෞතික මතකය රාමු (frames) ලෙසත් එකම ප්‍රමාණයේ කොටස්වලට බෙදයි. පිටු වගුව (Page Table) මගින් පිටු අංකය → රාමු අංකයට සිතියම් ගත කරයි. වලංගුතා බිට්ටුව (validity bit) = 0 නම් එම පිටුව භෞතික මතකයේ නැත → පිටු දෝෂය (page fault) — OS එය ද්විතීයික මතකයෙන් ගෙන ඒමට සිදු වේ.
  • අතථ්‍ය ලිපිනය (Virtual address) = පිටු අංකය + පිටුව තුළ පිහිටීම (offset).
    පිටු ප්‍රමාණය 4 KB = 2¹² → offset සඳහා බිට්ටු 12ක්; 16-bit ලිපිනයක ඉතිරි බිට්ටු 4 = පිටු අංකය.
    උදා: virtual 0001 0001 0001 0001 → පිටුව 0001, offset 0001 0001 0001. පිටු වගුවෙන් පිටුව 1 → රාමුව 0101 නම් physical = 0101 0001 0001 0001
  • අතථ්‍ය මතකය (Virtual Memory): ද්විතීයික මතකය භාවිතයෙන් භෞතික මතකයට වඩා විශාල මතකයක් ලබා දේ.
  • Swapping: මතක හිඟයකදී සම්පූර්ණ ක්‍රියාවලියක් තැටියට ගෙන යාම (මතකය නිදහස් කර ගැනීමට).
  • Thrashing: පිටු දෝෂ හුවමාරුවටම වැඩි කාලයක් ගත වීම — කාර්යක්ෂමතාව බිඳ වැටේ.
  • ඛණ්ඩනය (Fragmentation): අභ්‍යන්තර — පිටුවක් තුළ නාස්ති වන ඉඩ; බාහිර — මතකයේ විසිරුණු කුඩා හිස් කොටස්.
  • ඛණ්ඩකරණය (Segmentation): තාර්කික කොටස් (code, data, stack) ලෙස වෙනස් ප්‍රමාණයේ බෙදීම.

5. ගොනු පද්ධතිය (File System)

  • ගොනු වෙන් කිරීමේ ක්‍රම: ① අනුක්‍රමික/සන්තත (Contiguous) ② සම්බන්ධිත — FAT (ඛණ්ඩ දාමයක්; අවසන් ඛණ්ඩය −1) ③ දර්ශකිත (Indexed — inode) ④ සමූහකරණය (Clustered)
  • FAT කියවීම: නාමාවලි ඇතුළත් කිරීම (directory entry) = ගොනුවේ පළමු ඛණ්ඩයේ අංකය. ඉන්පසු FAT හි දාමය අනුගමනය කරන්න. 102→103→(-1) යනු ඛණ්ඩ 102, 103 වලින් සමන්විත ගොනුවකි (ආරම්භය 102).
  • ඛණ්ඩ ප්‍රමාණය (block size) තෝරා ගැනීම:
    • කුඩා ඛණ්ඩ: FAT විශාල වේ, දාමය දිගු වේ → සෙවීමට වැඩි කාලයක් හා පරිපාලන පිරිවැය; කුඩා ගොනු සඳහා හොඳයි
    • විශාල ඛණ්ඩ: අභ්‍යන්තර ඛණ්ඩනය — ගොනුව කුඩා වුවත් සම්පූර්ණ ඛණ්ඩයම වෙන් වී ඉඩ නාස්ති වේ
  • ගොනු පද්ධති: FAT16/FAT32 (සරල, පැරණි, 4 GB සීමාව), NTFS (ජර්නලකරණය, අවසර, සංකේතනය, විශාල ගොනු), ext4, APFS
  • නඩත්තු කාර්යයන්: ඛණ්ඩකරණය ඉවත් කිරීම (defragmentation), උපස්ථ (backup), තැටි සුපිරික්සුම (disk cleanup)

6. මළ අගුල (Deadlock)

ක්‍රියාවලි දෙකක් හෝ වැඩි ගණනක් එකිනෙකා මුදා හරින සම්පතක් එනතුරු අනන්තව බලා සිටීම.

මළ අගුලක් ඇති වීමට අවශ්‍ය කොන්දේසි 4 (සියල්ලම එකවර):

  1. අන්‍යෝන්‍ය බැහැර කිරීම (Mutual exclusion) — සම්පතක් එක් වේලාවක එක් ක්‍රියාවලියකට පමණයි
  2. රඳවා ගෙන බලා සිටීම (Hold and wait) — සම්පතක් රඳවාගෙන තවත් සම්පතක් බලා සිටීම
  3. පූර්ව අයිතියක් නොමැති වීම (No preemption) — සම්පත් බලෙන් ලබා ගත නොහැක
  4. චක්‍රීය බලා සිටීම (Circular wait) — ක්‍රියාවලි වලල්ලක් ලෙස බලා සිටීම

කළමනාකරණය: වැළැක්වීම (prevention — ඉහත කොන්දේසියක් බිඳ දැමීම), මග හැරීම (avoidance — Banker's algorithm), හඳුනා ගැනීම හා යථා තත්ත්වයට පත් කිරීම, නොසලකා හැරීම.

🎯 2025 A4 ප්‍රශ්නයේ ආකාරය "OS→P0→OS→P1→OS→P0..." දුන් විට:
• P0 → P1 සන්දර්භ මාරුවේදී P1 හි සිදුවන තත්ත්ව සංක්‍රාන්තිය: Ready → Running (P1 සූදානම්ව සිටි බැවින්)
• P0 දෙවන වරටත් නැවත ආරම්භ වූ ස්ථානයෙන්ම ක්‍රියාත්මක වන්නේ: PCB හි සුරැකි සන්දර්භය (program counter, registers) යළි පූරණය කිරීමෙනි
• අවහිර තත්ත්වයට යැවීමේ වාසිය: CPU නිෂ්ක්‍රීය නොවී වෙනත් ක්‍රියාවලියක් ක්‍රියාත්මක කරයි

4. ස්ථල විද්‍යාව (Topology)

තාරකා (Star)එක් කේබලයක් කැඩුනහොත් අනෙක් උපාංගවලට බලපෑමක් නැත; දෝෂ හඳුනා ගැනීම පහසුයි; පුළුල් කිරීම පහසුයිමධ්‍යම උපාංගය (hub/switch) බිඳ වැටුනහොත් ජාලයම නතර වේ; කේබල් වැඩියි
වලය (Ring)ගැටුම් නැත (token), පුරෝකථනය කළ හැකි ක්‍රියාකාරිත්වයඑක් උපාංගයක් බිඳ වැටුනහොත් සම්පූර්ණ වලයට බලපායි
දැල් (Mesh)උපරිම විශ්වාසනීයත්වය, විකල්ප මාර්ග, දෝෂ ඉවසීමකේබල් හා පිරිවැය ඉතා වැඩියි (n(n−1)/2)
වෘක්ෂ (Tree) / දෙමුහුන් (Hybrid)පුළුල් කළ හැකි, ධූරාවලිකමූල නෝඩය මත යැපීම

ආරක්ෂක යාන්ත්‍රණයන්

  • සංකේතනය (Encryption): සමමිතික (Symmetric — එකම යතුර; AES, DES — වේගවත්) හා අසමමිතික (Asymmetric — පොදු/පුද්ගලික යතුරු යුගලය; RSA — යතුරු හුවමාරුවට)
  • සරල සංකේතනය (Caesar cipher): "ADD → CEE" යනු +2 විස්ථාපනයකි; යතුර = 2. "ECD" ලැබුනොත් මුල් පණිවිඩය = "CAB" (−2). 2024 ප්‍රශ්නයක්
  • හැෂින්ග් (Hashing): ඒක දිශානුගතයි (irreversible) — මුරපද ගබඩා කිරීම, දත්ත අඛණ්ඩතාව (MD5, SHA-256)
  • ඩිජිටල් අත්සන (Digital Signature): සපයන්නේ — ① සත්‍යාපනය (authentication) ② අඛණ්ඩතාව (integrity) ③ ප්‍රතික්ෂේප කළ නොහැකි බව (non-repudiation). 2025 ප්‍රශ්නයක්
  • ඩිජිටල් සහතිකය (Certificate) හා CA — පොදු යතුරේ හිමිකරු සහතික කරයි
  • SSL/TLS, HTTPS, VPN, ෆයර්වෝලය, IDS/IPS, ප්‍රති-වයිරස, ද්වි-සාධක සත්‍යාපනය (2FA), සුරක්ෂිත මුරපද ප්‍රතිපත්ති, උපස්ථ (backup), යාවත්කාලීන කිරීම (patching)
  • සංකල්ප 3 (CIA): රහස්‍යතාව (Confidentiality), අඛණ්ඩතාව (Integrity), ප්‍රාප්තිය (Availability)
06 දත්ත සමුදාය කළමනාකරණ පද්ධති (B කොටසේ ප්‍රශ්න 9)

1. මූලික සංකල්ප

  • දත්ත සමුදාය (Database) — එකිනෙකට සම්බන්ධ දත්ත එකතුවක්. DBMS — එය නිර්මාණය කිරීමට හා කළමනාකරණයට යොදන මෘදුකාංගය (MySQL, Oracle, PostgreSQL, SQL Server, MS Access, SQLite).
  • DBMS වල වාසි: දත්ත අනුපිටපත්කරණය අඩුයි, අනුකූලතාව (consistency), බෙදා ගැනීම, ආරක්ෂාව හා ප්‍රවේශ පාලනය, උපස්ථ/ප්‍රතිසාධනය, ස්වාධීනත්වය (data independence), බහු පරිශීලක සහාය, අඛණ්ඩතා නීති. අවාසි: පිරිවැය, සංකීර්ණත්වය, දෘඪාංග අවශ්‍යතාව, එක් ස්ථානයක බිඳ වැටීමකදී සියල්ලටම බලපෑම, විශේෂඥ කාර්ය මණ්ඩලයක් අවශ්‍ය වීම.
  • පද: සත්තාව (Entity), ගුණාංගය (Attribute), වාර්තාව/ටුපලය (Record/Tuple), ක්ෂේත්‍රය (Field), වගුව (Relation/Table), වසම (Domain), දර්ශකය (Index), දර්ශනය (View)

2. යතුරු (Keys)

යතුරඅර්ථය
අපේක්ෂක යතුර (Candidate key)වාර්තාවක් අනන්‍යව හඳුනා ගත හැකි ඕනෑම ගුණාංගයක්/සංයෝගයක්
ප්‍රාථමික යතුර (Primary key)තෝරා ගත් අපේක්ෂක යතුර; හිස් නොවිය යුතුයි (NOT NULL), අනන්‍ය විය යුතුයි
විකල්ප යතුර (Alternate key)ප්‍රාථමික යතුර ලෙස තෝරා නොගත් අපේක්ෂක යතුරු
සංයුක්ත යතුර (Composite key)ගුණාංග දෙකක් හෝ වැඩි ගණනකින් සැදුම් ලත් යතුර
විදේශීය යතුර (Foreign key)වෙනත් වගුවක ප්‍රාථමික යතුරට යොමු වන ගුණාංගය — සම්බන්ධතාව ඇති කරයි
අධි යතුර (Super key)අනන්‍යව හඳුනා ගන්නා ඕනෑම ගුණාංග එකතුවක් (අනවශ්‍ය ගුණාංග ද තිබිය හැක)

3. සත්තා–සම්බන්ධතා සටහන (ER Diagram)

  • සංකේත: සෘජුකෝණාස්‍රය = සත්තාව; ඉලිප්සය = ගුණාංගය; දියමන්තිය = සම්බන්ධතාව; ද්විත්ව සෘජුකෝණාස්‍රය = දුර්වල සත්තාව; ද්විත්ව ඉලිප්සය = බහු අගය ගුණාංගය (multivalued); ඉරි සහිත ඉලිප්සය = ව්‍යුත්පන්න (derived) ගුණාංගය
  • සම්බන්ධතා: 1:1 · 1:M · M:N (අනුපාතිකත්වය — cardinality) හා සහභාගිත්වය (optionality — සම්පූර්ණ/අර්ධ)
  • M:N සම්බන්ධතාවක් සැමවිටම නව වගුවක් බවට පත් වේ (සම්බන්ධක වගුව — සම්බන්ධතාවයේ ඕනෑම ගුණාංගයක් ද එහි පැමිණේ).
  • 1:M → "M" පැත්තේ වගුවට "1" පැත්තේ ප්‍රාථමික යතුර විදේශීය යතුරක් ලෙස එක් කරන්න.
  • 1:1 → විදේශීය යතුර දෙපැත්තෙන් ඕනෑම එකකට (හෝ අනිවාර්ය සහභාගිත්වය ඇති පැත්තට) යොදන්න.
  • සෑම විටම ප්‍රාථමික යතුරු යටින් ඉරි අඳින්න (underline). ප්‍රශ්නයේ වරහන් තුළ දී ඇති පදම භාවිතා කරන්න.

EVENT(EventID, ENAME, StartDate, EndDate, ClubID)  ← 1:M (Club → Event)

      ↳ StuID → STUDENT, EventID → EVENT (විදේශීය යතුරු)

4. සාමාන්‍යකරණය (Normalization) — සෑම වසරකම එනවා!

සාමාන්‍ය ආකාරයකොන්දේසියකළ යුත්තේ
1NFසියලු අගයන් පරමාණුක (atomic) විය යුතුයි; පුනරාවර්තන කණ්ඩායම් (repeating groups) නොතිබිය යුතුයි; සෑම වාර්තාවක්ම අනන්‍ය විය යුතුයිබහු අගය ඇති කොටස් වෙනම වාර්තා හෝ වගු බවට පත් කරන්න
2NF1NF හි තිබිය යුතුයි + අර්ධ පරායත්තතා (partial dependency) නොතිබිය යුතුයි — සංයුක්ත PK එකක කොටසක් මත පමණක් රඳා පවතින ගුණාංග තිබිය යුතු නැතඅර්ධ පරායත්ත ගුණාංග වෙනම වගුවකට ගෙන යන්න
3NF2NF හි තිබිය යුතුයි + සංක්‍රාම්‍ය පරායත්තතා (transitive dependency) නොතිබිය යුතුයි — PK නොවන ගුණාංගයක් තවත් PK නොවන ගුණාංගයක් මත රඳා පැවතීමසංක්‍රාම්‍ය පරායත්ත ගුණාංග වෙනම වගුවකට ගෙන යන්න
BCNFසෑම නිර්ණායකයක්ම (determinant) අපේක්ෂක යතුරක් විය යුතුයි3NF හි විරල ගැටළු විසඳයි
විභාගයේදී "In which normal form does this table exist? Justify" ආවොත්
① සියලු අගයන් පරමාණුකද? → නැතිනම් 1NF නොවේ (UNF). ඔව් නම් 1NF වේ.
② සංයුක්ත ප්‍රාථමික යතුරක් තිබේද? එහි කොටසක් මත පමණක් රඳා පවතින ගුණාංග තිබේද? → 2NF නොවේ (1NF වේ).
③ PK නොවන → PK නොවන රඳා පැවැත්මක් (transitive) තිබේද? → 3NF නොවේ (2NF වේ).
සාධාරණීකරණය (justify) කිරීමට උදාහරණයක්ම දෙන්න: "Stu_ID → Stu_Name, Phone; Event_ID → Event_Type, Event_Fee — මේවා සම්පූර්ණ සංයුක්ත යතුර මත නොව එහි කොටසක් මත පමණක් රඳා පවතී, එබැවින් අර්ධ පරායත්තතාවක් ඇත → 1NF වේ, 2NF නොවේ." 
ඊළඟ සාමාන්‍ය ආකාරයට පරිවර්තනය කිරීම (1NF → 2NF උදාහරණය):
STUDENT(Stu_ID, Stu_Name, Phone)
EVENT(Event_ID, Event_Type, Event_Fee)
PARTICIPATION(Stu_ID, Event_ID, Services, Start_Date, End_Date)

  • NoSQL — ව්‍යුහගත නොවූ/විශාල දත්ත සඳහා; ලේඛන (document), යතුරු-අගය (key-value), තීරු (column), ප්‍රස්ථාර (graph) — MongoDB, Redis, Cassandra

උදා: ආරක්ෂාව, වේගය (තත්පර 3ක් ඇතුළත ප්‍රතිචාර), විශ්වාසනීයත්වය, පුළුල් කළ හැකි බව, භාවිත පහසුව (usability), සමගාමී පරිශීලකයන් 100කට සහාය

4. දත්ත ප්‍රවාහ සටහන (DFD)

සංකේතයනමවිස්තරය
◯ / වෘත්තයක්‍රියාවලිය (Process)දත්ත පරිවර්තනය කරයි — "1.0 ඇණවුම් ලබා ගැනීම" ලෙස අංකනය කරයි
▭ සෘජුකෝණාස්‍රයබාහිර සත්තාව (External entity)පද්ධතියෙන් පිටත දත්ත ප්‍රභවය/ගමනාන්තය (පාරිභෝගිකයා, කළමනාකරු)
▭ විවෘත සෘජුකෝණාස්‍රය / දෙපැති රේඛාදත්ත ගබඩාව (Data store)දත්ත තැන්පත් කරන ස්ථානය — D1, D2 ලෙස නම් කරයි
→ ඊතලයදත්ත ප්‍රවාහය (Data flow)දත්ත ගමන් කරන දිශාව — සෑමවිටම නම් කරන්න

DFD නීති (context diagram සිට level 1 දක්වා):

  • දත්ත ප්‍රවාහයක් සෑමවිටම ක්‍රියාවලියක් හරහා යා යුතුයි — ගබඩාවක සිට ගබඩාවකට හෝ බාහිර සත්තාවක සිට ගබඩාවකට කෙලින්ම දත්ත ගලා යා නොහැක.
  • සන්දර්භ සටහනේ (Context / Level 0) එක් ක්‍රියාවලියක් පමණයි (සම්පූර්ණ පද්ධතිය). Level 1 හි එය උප ක්‍රියාවලිවලට බෙදේ.
  • සෑම ක්‍රියාවලියකටම අවම වශයෙන් එක් ආදානයක් හා එක් ප්‍රතිදානයක් තිබිය යුතුයි.
  • Level 1 හි ඇති ආදාන/ප්‍රතිදාන ප්‍රවාහයන් සන්දර්භ සටහනේ ඒවාට ගැලපිය යුතුයි (balancing).
  • ක්‍රියාවලි විස්තරය (process description) — සෑම ක්‍රියාවලියක්ම කරන්නේ කුමක්දැයි වාක්‍යයකින් (2024 ප්‍රශ්නයක්): උදා: "2. අවසන් බිල්පත සකස් කිරීම — ආගන්තුකයාගේ කාලසීමාවට අනුව කාමර ගාස්තු එකතු කර, අවන්හලේ හා සෞඛ්‍ය මධ්‍යස්ථානයේ ගනුදෙනු එකතු කර, 10% සේවා ගාස්තුවක් එක් කර අවසන් මුදල ගණනය කරයි."

5. සංවර්ධන ආකෘති (Development Models)

ආකෘතියලක්ෂණයයොදන අවස්ථාව
දිය ඇලි (Waterfall)අනුපිළිවෙලින් එක් අවධියක් අවසන් කර ඊළඟට; ආපසු හැරී යාමක් නැතඅවශ්‍යතා පැහැදිලිව නිශ්චිත විට. අවශ්‍යතා විශ්ලේෂණය ඉතා වැදගත් — පසුව වෙනස් කිරීමට අපහසුයි (2023 ප්‍රශ්නයක්)
මූලාකෘති (Prototyping)ක්‍රියාකාරී ආකෘතියක් ඉක්මනින් තනා පරිශීලක ප්‍රතිචාර ලබා ගනීඅවශ්‍යතා අපැහැදිලි විට. වාසිය: පරිශීලක අවශ්‍යතා පැහැදිලි කර ගත හැකියි, වැරදි වැටහීම් අඩුයි, සැලසුම් දෝෂ කලින් හඳුනා ගත හැකියි
සර්පිල (Spiral)අවදානම් විශ්ලේෂණය සහිත පුනරාවර්තී චක්‍රවිශාල, අවදානම් සහිත ව්‍යාපෘති
කඩිනම් (Agile / Scrum)කෙටි පුනරාවර්තන (sprints), නිරන්තර පාරිභෝගික සහභාගිත්වය, ක්‍රියාත්මක මෘදුකාංගයට ප්‍රමුඛතාවඅවශ්‍යතා නිතර වෙනස් වන විට
RADවේගවත් සංවර්ධනය — ප්‍රතිචක්‍රීය මෙවලම් හා පුනරාවර්තී සැලසුම්ඉක්මන් බෙදා හැරීමක් අවශ්‍ය විට

6. පරීක්ෂණය (Testing)

මට්ටමපරීක්ෂා කරන්නේ
ඒකක පරීක්ෂණය (Unit testing)තනි මොඩියුලය/ශ්‍රිතයක් වෙන වෙනම
ඒකාබද්ධතා පරීක්ෂණය (Integration testing)මොඩියුල කිහිපයක් එකට සම්බන්ධ කළ විට ඒවා අතර දත්ත හුවමාරුව හා අතුරු මුහුණත් නිවැරදිව ක්‍රියා කරන්නේද යන්න (2023 ප්‍රශ්නයක්)
පද්ධති පරීක්ෂණය (System testing)සම්පූර්ණ පද්ධතියම — ක්‍රියාකාරී හා ක්‍රියාකාරී නොවන අවශ්‍යතා
පිළිගැනුම් පරීක්ෂණය (Acceptance)පරිශීලකයා විසින් සැබෑ දත්ත සමග (alpha: සංවර්ධක පරිසරයේ / beta: සැබෑ පරිසරයේ)
ප්‍රතිගාමී පරීක්ෂණය (Regression)වෙනස් කිරීමකින් පසු පැරණි ක්‍රියාකාරිත්වයන්ට හානියක් නොවූ බව සහතික කිරීම

ඉහළ-පහළ (top-down) — ප්‍රධාන මොඩියුලයේ සිට, නොමැති ඒවා වෙනුවට stubs; පහළ-ඉහළ (bottom-up) — කුඩා මොඩියුලවල සිට, drivers භාවිතයෙන්.

7. යෙදවීමේ ක්‍රම (Deployment Strategies)

ක්‍රමයවිස්තරයවාසි / අවාසි
සෘජු (Direct / Big bang)පැරණි පද්ධතිය එකවරම ඉවත් කර නව පද්ධතිය ක්‍රියාත්මක කිරීමලාභදායී, සරල; අවදානම ඉතා ඉහළයි — බිඳ වැටුනහොත් ආපසු යාමක් නැත
සමාන්තර (Parallel)පැරණි හා නව පද්ධති දෙකම එකවර ක්‍රියාත්මක කිරීමආරක්ෂිතයි (සංසන්දනය කළ හැකියි); දෙගුණයක් වැඩ හා වියදම
නියමු (Pilot)මුලින්ම එක් ශාඛාවක/දෙපාර්තමේන්තුවක (කුඩා පරිමාණයෙන්) ක්‍රියාත්මක කිරීමසීමිත අවදානම; සාර්ථක නම් අනෙක් තැන්වලට ව්‍යාප්ත කළ හැකියි
අදියර (Phased)මොඩියුලයෙන් මොඩියුලය ක්‍රමයෙන්කළමනාකරණය කළ හැකියි; සම්පූර්ණ කිරීමට කාලය වැඩියි

def binary_search(a, key):
    low, high = 0, len(a) - 1
    while low <= high:
        mid = (low + high) // 2
        if a[mid] == key: return mid
        elif a[mid] < key: low = mid + 1
        else: high = mid - 1
    return -1

  • URL ව්‍යුහය: https://www.example.com:443/path/page.php?x=1#top (ප්‍රොටොකෝලය :// වසම :වරාය /මාර්ගය ?පරාමිති #නැංගුරම)

4. Arduino වැඩසටහනක ව්‍යුහය (firmware)

const int SensorP = 9;     // සංවේදකයේ පින් අංකය
const int BuzzerP = 8;

void setup() {                    // එක් වරක් පමණයි
    pinMode(SensorP, INPUT);      // INPUT / INPUT_PULLUP / OUTPUT
    pinMode(BuzzerP, OUTPUT);
    Serial.begin(9600);           // අනුක්‍රමික සන්නිවේදනය
}

void loop() {                     // නැවත නැවත
    int senState = digitalRead(SensorP);          // HIGH හෝ LOW
    if (senState == HIGH) {
        tone(BuzzerP, 262);                       // 262 Hz ශබ්දය
    } else {
        noTone(BuzzerP);
    }
    delay(100);
}
